# 북마크 매니저 (Chrome Extension)

북마크 바(Bookmarks Bar)의 북마크를 목록으로 보고, 제목/주소를 편집하고,
특정 도메인을 가진 북마크를 일괄 수정하며, 추가/삭제할 수 있는 Chrome 확장 프로그램.

## 개발 스택

- Manifest V3
- TypeScript + React + Vite (`@crxjs/vite-plugin`)

## 시작하기

```bash
npm install
npm run build      # dist/ 생성
# 개발 중 자동 재빌드:
npm run dev
```

## Chrome에 로드하기

1. `npm run build` 실행 (또는 `npm run dev`로 watch 모드 실행)
2. `chrome://extensions` 접속 → 우측 상단 "개발자 모드" 켜기
3. "압축해제된 확장 프로그램을 로드합니다" 클릭 → 이 프로젝트의 `dist` 폴더 선택
4. 확장 아이콘을 클릭하면 관리 페이지가 새 탭으로 열립니다.

`npm run dev`로 watch 중이면 코드 수정 시 `dist`가 갱신되고,
`chrome://extensions`에서 새로고침 버튼을 누르면 반영됩니다
(HMR로 대부분 자동 반영되지만 background/manifest 변경 시에는 수동 새로고침이 필요할 수 있습니다).

## 아이콘

확장 아이콘의 원본은 `assets/icon.svg`(32·48·128px용)와 `assets/icon-small.svg`(16px용, 작은 크기에서
뭉개지지 않도록 단순화)입니다. `public/icons/icon-{16,32,48,128}.png`는 이 SVG를 해당 크기의 PNG로
렌더링한 것이며(Chrome 확장 아이콘은 PNG만 지원), 원본을 고치면 PNG도 다시 만들어 교체해야 합니다.

## 기능

관리 페이지의 메뉴(북마크 목록 · 북마크 추가 · 스크린샷 설정 · 중복 제거 · 도메인 일괄 수정 · 백업)는
평소 왼쪽에 접혀 있고, 왼쪽 위의 떠 있는 ☰ 버튼을 누르면 나타납니다. 메뉴를 고르면 메뉴가 닫히고
해당 화면이 가운데에 표시됩니다 (메뉴 바깥을 누르거나 Esc를 눌러도 닫힘).
현재 메뉴는 주소의 `#해시`(예: `#capture`)에 남아 새로고침해도 유지됩니다.

- **목록**: 북마크 바의 폴더와 북마크를 바둑판(타일) 형태로 표시. 폴더를 클릭하면 그 폴더 안의
  항목만 보이며, 상단 경로(북마크 바 › 폴더 › ...)를 눌러 상위 폴더로 이동. 북마크를 클릭하면 새 탭으로 열림.
  타일을 드래그해 다른 타일의 왼쪽/오른쪽에 놓으면 순서가 바뀌며 Chrome 북마크에도 그대로 반영됨
  (폴더는 폴더끼리, 북마크는 북마크끼리. 검색 중에는 드래그 불가). 북마크나 폴더를 폴더 타일 위에
  놓으면 그 폴더 안(맨 끝)으로 이동 (폴더끼리는 타일 양쪽 가장자리가 순서 바꾸기, 가운데가 안으로 넣기).
  검색창 옆 **+ 새 폴더** 버튼으로 이름을 입력하면 지금 보고 있는 폴더의 맨 앞에 폴더를 만듦
- **폴더 편집**: 폴더 타일에 마우스를 올리면 나오는 "편집" 버튼으로 이름 변경, 위치(상위 폴더) 변경,
  삭제 (안의 북마크·하위 폴더까지 함께 삭제되며 확인 창에 개수 표시)
- **썸네일**: 북마크된 사이트에 들어가 로딩이 끝나면 화면을 자동으로 캡처해 타일 썸네일로 표시.
  타일에 마우스를 1초 이상 올려두면 스크린샷이 크게 표시되고 그 아래에 제목과 주소가 나옴(이때는 툴팁 대신).
  캡처는 탭이 화면에 보일 때만 가능하므로
  백그라운드 탭은 해당 탭으로 전환할 때 찍히며, 1시간 안에 찍은 썸네일이 있으면 다시 찍지 않음.
  북마크 주소에서 다른 주소로 리다이렉트되는 사이트는 최종적으로 로드된 화면을 그 북마크의
  썸네일로 저장. (이를 위해 모든 사이트에 대한 호스트 권한 `<all_urls>`와 `webNavigation` 권한을 사용)
  자동 캡처는 **북마크(북마크 바와 하위 폴더)에 있는 주소를 열었을 때만** 동작하며, 주소는 페이지 단위로
  일치해야 함 (`example.com` 북마크로 `example.com/news`는 캡처하지 않음). 북마크에 없는 사이트는
  처음 방문이든 아니든 캡처하지 않으며, 페이지 위 "북마크에 추가" 버튼으로 추가할 때만 그 순간을 캡처.
  스크린샷 설정 화면에도 같은 안내("캡처는 언제 되나요?")를 표시
- **스크린샷 설정**: 썸네일 캡처는 이 목록에 등록한 도메인(하위 도메인 포함)의 북마크에서만
  동작하며, 목록에 없는 사이트는 캡처하지 않음. 도메인 또는 주소를 붙여넣어 추가/삭제.
  **모든 사이트**를 체크하면 목록과 관계없이 모든 북마크를 캡처하고, 목록에 없는 사이트에는
  좌측 하단에 버튼이 나타남. 이때도 목록에 등록한 사이트는 각자의 버튼 설정(표시 여부·위치)을 따르며,
  체크를 해제하면 원래대로 목록의 사이트만 캡처.
  캡처한 스크린샷은 외부로 전송되지 않고 이 기기의 현재 Chrome 프로필에만 저장됨
  (프로필 폴더의 `IndexedDB/chrome-extension_<확장 ID>_0.indexeddb.leveldb`). 확장을 삭제하면 함께
  지워지므로 보관하려면 ZIP 내보내기를 사용. 화면에도 같은 안내를 표시.
  사이트마다 **추가 버튼 표시**를 켜면 그 사이트를 볼 때 화면 모서리(좌측/우측 상단·하단 중 선택)에
  "북마크에 추가" 버튼이 나타나고, 누르면 저장할 폴더를 골라 현재 페이지를 북마크로 추가하면서
  그 순간의 화면을 캡처해 새 북마크의 썸네일로 저장 (버튼과 선택 창은 캡처 전에 숨김).
  옆의 **캡처** 버튼은 현재 페이지가 이미 북마크에 있을 때만 활성화되며, 누르면 지금 화면을
  다시 캡처해 기존 썸네일을 교체
- **파비콘**: 캡처 이미지가 없는 북마크는 제목의 첫 글자 대신, 방문한 적이 있어 Chrome에 저장된
  파비콘이 있으면 그 파비콘을 표시 (`favicon` 권한 사용. 방문 기록 권한은 쓰지 않음)
- **검색**: 제목·주소·폴더명으로 전체 폴더에서 검색 (결과에 폴더 경로 함께 표시)
- **편집**: 타일에 마우스를 올리면 나오는 "편집" 버튼으로 제목/주소/폴더 수정 (폴더를 바꾸면
  그 폴더의 맨 끝으로 이동). 팝업 바깥을 클릭하면 닫힘. 스크린샷이 있으면
  편집 창의 "이미지 제거"로 그 이미지만 삭제
- **추가**: 제목/주소와 저장할 폴더(북마크 바 또는 하위 폴더)를 선택해 새 북마크 생성.
  같은 화면의 **폴더 추가**로 이름과 위치를 골라 새 폴더 생성 (항상 선택한 위치의 맨 앞에 만들어짐)
- **삭제**: 편집 창의 삭제 버튼 (확인 후 삭제)
- **도메인 일괄 수정**: "찾을 도메인"과 "바꿀 도메인"을 입력하면 일치하는 모든 북마크의
  호스트(도메인) 부분만 교체 (경로/쿼리스트링은 유지). "하위 도메인 포함" 옵션으로
  `www.old.example.com` 같은 서브도메인도 함께 바꿀지 선택 가능. 적용 전 영향받는
  북마크 미리보기와 확인 다이얼로그 제공. 바뀐 북마크에 연결된 캡처 이미지도 새 주소로 옮김
- **중복 제거**: "중복 제거" 버튼을 누르면 같은 주소를 가진 북마크를 그룹으로 표시
  (스킴/도메인 대소문자, 끝의 "/" 차이는 무시). 기본으로 각 주소에서 가장 먼저 추가된
  1개만 남기고 나머지가 선택되며, 체크박스로 조정한 뒤 "선택 삭제"로 한 번에 삭제.
- **백업**: 저장된 스크린샷을 **ZIP으로 내보내기/가져오기** (로그인 불필요, 다른 PC나 프로필로
  옮길 때도 사용). 가져올 때 같은 주소의 이미지가 이미 있으면 더 최근에 찍은 쪽을 남김.

## 보류된 기능: Google Drive 백업

스크린샷을 내 Google Drive에도 자동으로 백업하는 기능을 만들었지만, **현재는 사용하지 않을 것
같아 기능에서 제외했습니다.** 코드(`src/drive.ts`, `src/manage/components/DriveSync.tsx` 등)는 그대로
남아 있고, 기본 빌드에서는 꺼진 상태입니다.

- 꺼져 있을 때: 백업 메뉴에 Drive 항목이 보이지 않고, 업로드·이동 등 Drive 관련 동작을 전혀 하지 않으며,
  manifest에서 `identity` 권한과 `oauth2` 항목도 빠집니다. 화면 안내 문구에서도 Drive 언급이 사라집니다.
- 켜져 있을 때 하던 일:
  - Chrome의 `chrome.identity`로 Google 계정에 로그인 (Firebase 등 별도 인증 서비스 불필요).
    권한 범위는 `drive.file`이라 이 확장이 만든 폴더/파일에만 접근
  - 썸네일을 캡처할 때마다 내 드라이브의 지정한 폴더(기본 "Bookmark Thumbnails")에 업로드.
    같은 주소는 같은 파일을 덮어씀 (파일 이름은 `도메인_해시.jpg`)
  - "기존 썸네일 전체 업로드"로 아직 올라가지 않은 썸네일을 한 번에 업로드
  - 도메인 일괄 수정 시 Drive 파일도 새 도메인 이름으로 다시 올리고 옛 파일은 삭제
  - 이미지 제거·ZIP 가져오기는 Drive 파일을 건드리지 않음 (가져온 이미지는 "전체 업로드"로 올림)

### 다시 켜는 방법

1. [Google Cloud Console](https://console.cloud.google.com/)에서 프로젝트를 만들고
   **API 및 서비스 > 라이브러리**에서 **Google Drive API**를 사용 설정
2. **OAuth 동의 화면** 구성: 사용자 유형 "외부", 게시 상태는 "테스트"로 두고
   **테스트 사용자**에 본인 Google 계정 추가
3. **사용자 인증 정보 > 사용자 인증 정보 만들기 > OAuth 클라이언트 ID**
   - 애플리케이션 유형: **Chrome 확장 프로그램**
   - 항목 ID: `chrome://extensions`에 표시되는 이 확장의 ID
     (압축해제 로드 시 ID는 `dist` 폴더 경로로 정해지므로 폴더를 옮기면 바뀜)
4. `.env.example`을 `.env.local`로 복사하고 `ENABLE_DRIVE_BACKUP=true`,
   `GOOGLE_OAUTH_CLIENT_ID`에 발급받은 ID 입력 (둘 다 있어야 켜짐)
5. `npm run build` 후 `chrome://extensions`에서 새로고침 (`identity` 권한이 추가됨)
6. 관리 페이지의 **백업 › Google Drive 백업**에서 로그인하면 이후 캡처되는 썸네일이 자동 업로드됨

## 스펙 확정 사항 (사용자 확인 완료)

- UI는 전용 관리 페이지(새 탭)로 제공하고, 확장 아이콘 클릭 시 열림
- "도메인 일괄 수정"은 도메인 문자열 찾기/바꾸기 방식 (URL 전체 정규식 아님)
- 대상 범위는 북마크 바 + 그 하위 폴더 (다른 북마크/모바일 북마크는 제외)
- 스택은 TypeScript + React + Vite

## 추가로 임의 판단한 부분

- 목록이 많을 수 있다는 점을 고려해 검색(필터) 기능을 추가함
- 새 북마크 추가 시 저장 폴더를 북마크 바 하위에서 선택할 수 있게 함 (기본값: 북마크 바 최상위)
- URL 유효성은 `new URL()` 파싱 성공 여부로 검증
